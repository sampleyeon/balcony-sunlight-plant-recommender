# RAG 식물 DB

추천엔진이 고른 식물을 LLM이 설명할 때, 근거로 쓰는 식물 카드와 벡터 DB 제작 코드입니다.

## 구성

| 경로 | 내용 |
| --- | --- |
| `cards/01_상추.md` ~ `30_골드크레스트.md` | 추천 대상 30종 카드 |
| `cards/그외/` | 과일·꽃 7종 (블루베리, 포도, 무화과, 화분국화, 미니장미, 레몬, 금귤) |
| `cards/그외_실내정원/` | 농사로 실내정원용 식물 API 207종 (자동 생성) |
| `cards/_양식.md` | 카드 양식 |
| `식물카드_목록.csv` | 카드 244장의 그룹, 분류, 출처 목록 |
| `make_garden_cards.py` | 실내정원 API 응답(JSON)으로 카드 21~30번과 `그외_실내정원` 카드 생성 |
| `notebooks/nongsaro_garden_*.ipynb` | 농사로 실내정원용 식물 API 받기 (Colab Secrets에 `NONGSARO_API_KEY`) |
| `notebooks/perenual_*.ipynb`, `scripts/perenual_*.py` | 국내 자료가 없는 허브·과일의 Perenual 자료 받기 (`PERENUAL_API_KEY`) |
| `notebooks/plant_vectordb_test.ipynb` | 카드 → 섹션 단위 청크 → bge-m3 임베딩 → Chroma 저장, 질문 5개 검색 테스트 |
| `농사로_자료확인_20261114.md` | 30종별 자료 출처 확인 기록 |
| `바질_재배정보.md` | 국내 자료가 부족한 바질의 해외 원예자료 요약 |

## 원칙

- 출처를 구할 수 없는 식물은 카드에 넣지 않았습니다.
- 카드의 `엔진 기준값`은 plant_data.csv 값을 그대로 옮겼고, 자료와 다른 점이 보이면 고치지 않고 표시만 했습니다.
- API 원본 응답 JSON과 API 키는 저장소에 넣지 않았습니다. 노트북을 실행하면 다시 받을 수 있습니다.

## 검색 방식

1. 카드의 `## ` 섹션 하나를 청크 하나로 만들고, 앞에 `[식물 이름] 섹션`을 붙입니다 (2,209개).
2. 질문에 식물 이름이나 별칭이 있으면 그 식물로 필터링해서 찾습니다.
3. DB에 없는 식물을 물으면 "자료 없음"으로 답합니다.
