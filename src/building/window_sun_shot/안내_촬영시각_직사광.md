# 21일 촬영 시각별 직사광 판정 (window_sun_shot.py)

그림자 래스터 `Shadow_20251021_HHMM_LST.tif`를 찍은 시각(07:00~17:30, 30분 간격, 22장)마다, 시나리오 세대의 창에 직사광이 드는지 판정합니다. 기준일은 엔진과 같은 **매달 21일**이고, 12개월(2025-10 ~ 2026-09)을 모두 계산합니다.

판정 방식은 `window_sun.py`와 같습니다. 태양 위치를 구하고, 해가 창 정면 ±90° 안에 있는지 보고, 창 높이에서 태양 쪽으로 DSM을 따라가며 건물에 막히는지 봅니다. 다른 점은 10분 구간이 아니라 **그 시각 한 순간**을 판정한다는 것과, 직사광이 없으면 이유와 가린 건물을 같이 적는다는 것입니다.

## 실행 (QGIS)
1. `window_sun_shot.py`를 `C:\gis\` 에 넣습니다.
2. 플러그인 → 파이썬 콘솔 → 편집기 표시 → 열기 → `window_sun_shot.py` → ▶
3. 콘솔에서 볼 것:
   - `DSM: ...dsm_buf300_juso_202609.tif` → 신축 단지까지 채운 DSM을 쓰는 겁니다.
   - `촬영 시각 22개 (그림자 파일 이름에서): 07:00, 07:30, …` → gis 폴더 아래 Shadow 파일을 찾은 겁니다. 못 찾으면 "기본값"이라고 나오고 같은 22개 시각을 씁니다.
   - 마지막에 2025-10-21 표가 세대별로 한 줄씩 나옵니다.
4. 결과 파일 두 개가 gis 폴더에 생깁니다. 이 두 파일을 보내 주시면 표로 정리해 드릴게요.

시각을 바꾸려면 `SHOT_TIMES = ['09:00', '12:00', '15:00']`처럼 적으면 됩니다.

## 결과 파일
**window_sun_shot_table.csv**: 한 줄 = 세대 × 날짜, 칸 = 시각
- `O` 직사광 / `X` 건물에 가림 / `-` 해가 창 뒤쪽 / 빈칸 해 짐
- `direct_shots`: 그날 촬영 시각 중 직사광인 시각 수

**window_sun_shot_detail.csv**: 한 줄 = 세대 × 날짜 × 시각
| 열 | 뜻 |
|---|---|
| sun_alt, sun_az | 태양 고도·방위각(°, 북=0 시계방향) |
| angle_from_window | 해와 창 정면 사이 각도. 90° 이상이면 창 뒤쪽 |
| direct | 판정값. 1 직사광, 0 없음 |
| reason | 직사광 / 건물에 가림 / 해가 창 뒤쪽 / 해 짐 |
| blocker_dist_m, blocker_h_m | 가렸을 때 처음 막는 DSM 칸까지 거리와 그 칸 높이 |
| engine_slot | 엔진 방식(그 시각에 시작하는 10분 구간, 중앙 시각으로 판정) 값. `window_sun_detail.csv`의 같은 시각 값과 같아야 함 |
| ground_shadow_tif | 2025-10-21에만 채움. 창 바로 앞 **지면**의 UMEP 그림자 값(1 햇빛, 0 그림자) |

## 읽을 때 주의
- 맑은 날 기준입니다. 구름은 반영하지 않습니다.
- `ground_shadow_tif`는 지면 높이 값이라 1층 세대(C)에서만 `direct`와 직접 비교할 수 있습니다. 위층 세대는 지면이 그늘이어도 창은 햇빛일 수 있습니다.
- 지금 Shadow 파일은 옛 DSM(성북구 안 건물만, 신축 단지 없음)으로 만든 것이라, 신축 단지 근처에서는 지면 값과 판정이 어긋날 수 있습니다.
- 순간 판정과 `engine_slot`은 해가 막 가려지거나 나오는 시각에서만 다릅니다. 콘솔 마지막에 다른 칸 수가 나옵니다.
