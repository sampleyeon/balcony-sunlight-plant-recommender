# AI 심사위원 사용자 만족도 평가 안내

실제 사용자를 모을 수 없으므로, AI에게 가상 사용자(페르소나)를 맡겨 추천 결과를 평가한다.
"AI가 만든 걸 AI가 칭찬했다"는 지적을 피하기 위해 **블라인드 비교**, **고정 루브릭**, **반복**, **교차 모델**, **순서 편향 점검**을 넣는다. 현장 실측과 실제 사람 평가는 하지 않는다.

결과는 같은 폴더의 `AI심사_집계표.xlsx`에 입력하면 요약 시트가 자동으로 계산된다.

---

## 1. 평가 설계

| 항목 | 내용 |
|---|---|
| 비교 대상 | **기준안**: 일조를 무시한 일반 계절 재배 달력 추천 / **시스템안**: 층·방향·그림자(direct_h)와 기온을 반영한 추천 엔진 결과 |
| 블라인드 | 두 안을 "추천안 1", "추천안 2"로만 보여 준다. 어느 쪽이 시스템안인지는 회차마다 동전 던지기(또는 엑셀 `=RANDBETWEEN(1,2)`)로 정하고 집계표에만 적는다 |
| 시나리오 | A 장위동 꿈의숲대명루첸 18층 남동, B 정릉풍림아이원 7층 남, C 길음뉴타운 1층 남 |
| 심사위원 | 페르소나 4명 (아래 2장) |
| 반복 | 시나리오 × 페르소나마다 **5회**, 매번 **새 대화창**에서 실행 |
| 전체 횟수 | 3 시나리오 × 4 페르소나 × 5회 = **60회** (모델 하나 기준) |
| 교차 모델 | 같은 60회를 다른 AI 모델(예: Claude와 ChatGPT 또는 Gemini)로 한 번 더 돌린다. 한 모델의 취향이 아닌지 확인 |
| 순서 편향 | AI는 먼저 나온 안을 고르는 경향이 있어, 시스템안 위치(1번/2번)별 선호율을 따로 본다. 집계표가 자동 계산 |

### 기준안 만드는 법
집 정보 중 **지역(서울)과 현재 월만** 보고 만든 추천이다. 층, 창 방향, 직사광 시간은 쓰지 않는다.
예: 농사로(농촌진흥청) 텃밭 재배력에서 해당 월에 파종 가능한 베란다 작물 상위 3개.
세 시나리오 모두 같은 서울이므로 기준안은 **세 집이 똑같이** 나온다. 이게 정상이다.

### 시스템안 만드는 법
추천 엔진 결과(작물 상위 3개, 점수, 재배 시작 시기, 추천 이유)를 그대로 쓴다.

### 공정하게 만들기 위한 규칙
- 두 안의 **형식과 길이를 맞춘다**. 작물 3개, 작물마다 재배 시작 시기 한 줄과 이유 한 줄. 시스템안만 길거나 숫자가 많으면 그것만으로 점수가 올라간다.
- "AI가 만든", "우리 시스템" 같은 표현은 넣지 않는다.
- 평가 기준 월을 하나로 고정한다(예: 2026-10). 모든 회차가 같은 월을 쓴다.

## 2. 페르소나

| 코드 | 페르소나 | 설명 (프롬프트에 그대로 넣음) |
|---|---|---|
| P1 | 초보 1인 가구 | 20대 후반 직장 초년생. 식물을 키워 본 적이 거의 없고, 베란다에 작은 화분 몇 개를 두고 싶다. 실패하지 않는 것이 가장 중요하다. |
| P2 | 바쁜 맞벌이 직장인 | 30대 후반, 평일엔 늦게 귀가해서 물은 주 1회 정도만 줄 수 있다. 손이 덜 가고 수확이 확실한 작물을 원한다. |
| P3 | 텃밭 경험자 | 50대, 주말농장을 5년 해 봤다. 베란다로 옮겨 키우려 하며, 빛이 부족하면 무엇이 안 되는지 경험으로 안다. 근거가 부실한 추천은 믿지 않는다. |
| P4 | 원예 전문가 | 원예학 전공 연구원. 광량(일조 시간), 온도, 작물별 생육 조건이 맞는지를 전문가로서 엄격히 따진다. |

## 3. 프롬프트 (복사해서 사용)

`{ }` 부분만 바꿔 넣는다. 매 회차 **새 대화창**에서 실행한다.

```
당신은 지금부터 아래 인물이 되어 베란다 작물 추천 결과를 평가합니다.

[당신은]
{페르소나 설명}

[집 정보]
- 위치: 서울 성북구 {동 이름} {아파트 이름}
- 층수: {층}층, 베란다 창 방향: {방향}
- 이 창에 직사광이 드는 시간(맑은 날, 월 21일 기준): {월별 direct_h 표 또는 "10월 6.7시간, 11월 5.8시간, ..."}
- 서울 월평균 기온: {월별 기온}
- 평가 기준 시점: {2026년 10월}

[추천안 1]
{추천안 1 내용}

[추천안 2]
{추천안 2 내용}

[평가 방법]
두 추천안을 각각 아래 4개 항목에 대해 1~5점으로 매기세요. 점수 기준은 다음과 같습니다.

1. 환경 적합성: 이 집의 빛과 온도에 추천 작물이 맞는가
   1 = 이 환경에선 자라기 어려운 작물이 대부분 / 3 = 절반쯤 맞음 / 5 = 모두 이 환경에 잘 맞음
2. 실용성: 나(이 인물)의 생활과 경험 수준으로 따라 하기 쉬운가
   1 = 따라 하기 어려움 / 3 = 노력하면 가능 / 5 = 바로 시작할 수 있음
3. 설명성: 왜 이 작물과 이 시기인지 이유가 이해되는가
   1 = 이유가 없거나 이해 안 됨 / 3 = 대략 이해됨 / 5 = 내 집 조건과 연결해 명확히 이해됨
4. 신뢰도: 이 추천을 믿고 실제로 따르겠는가
   1 = 따르지 않겠다 / 3 = 반신반의 / 5 = 그대로 따르겠다

점수를 매긴 뒤 둘 중 어느 추천을 따르고 싶은지 하나를 고르세요. 정말 차이가 없으면 "동점"이라고 하세요.

[답변 형식] 아래 형식 그대로, 다른 말 없이 답하세요.
추천안1: 적합성=_, 실용성=_, 설명성=_, 신뢰도=_
추천안2: 적합성=_, 실용성=_, 설명성=_, 신뢰도=_
선택: 1 또는 2 또는 동점
이유: (한두 문장)
```

### 입력 예시 (B, 2026-10)

```
[집 정보]
- 위치: 서울 성북구 정릉동 정릉풍림아이원
- 층수: 7층, 베란다 창 방향: 남
- 이 창에 직사광이 드는 시간(맑은 날, 월 21일 기준):
  10월 6.7 / 11월 5.8 / 12월 5.7 / 1월 5.8 / 2월 6.8 / 3월 7.5 /
  4월 8.5 / 5월 7.0 / 6월 6.3 / 7월 7.0 / 8월 8.5 / 9월 7.5 (시간)
```

## 4. 교차 모델 평가

3장 프롬프트를 그대로 다른 AI 모델에 넣어 같은 60회를 돌린다. 시스템안 위치는 집계표 `모델2입력` 시트에 미리 정해 둔 값을 따른다.
두 모델이 같은 방향(둘 다 시스템안 선호 또는 둘 다 기준안 선호)이면 결과가 특정 모델의 취향이 아니라고 말할 수 있다.

---

## 5. 집계표 사용법 (`AI심사_집계표.xlsx`)

- **모델1입력** 시트: 한 회차 = 한 줄. 시나리오, 페르소나, 회차, 모델, `시스템위치`(시스템안이 1번이었으면 1, 2번이면 2), AI가 답한 점수 8개와 선택을 그대로 적는다. 오른쪽 회색 열은 자동 계산이다(시스템 선택 여부, 시스템·기준 평균).
- **모델2입력** 시트: 같은 구조, 두 번째 AI 모델 결과.
- **요약** 시트: 자동 계산.
  - 시스템 선호율 = 시스템안을 고른 비율 (동점은 0.5로 계산)
  - 항목별 평균 점수 (시스템안 vs 기준안)
  - 시나리오별·페르소나별 선호율
  - 모델 1 vs 모델 2 선호율 비교
  - 순서 편향: 시스템안이 1번일 때와 2번일 때 선호율 (차이 20%p 이하면 편향이 작다고 본다)
  - 반복 안정성: 같은 시나리오·페르소나 5회의 시스템 평균점수 표준편차 (0.5 이하면 안정적이라고 본다)

## 6. 보고서에 쓰는 법

- 주 평가는 객관적 평가(UMEP·천문연 대조, DLI·GDD 계산, 재배력 일치율)이고, AI 만족도는 **사용자 관점 보조 평가**로 둔다.
- 결과 문장 예: "AI 심사위원 4명(60회 블라인드 비교)에서 시스템 추천이 기준안보다 X% 더 선호되었고, 특히 저층(C)에서 Y%로 차이가 가장 컸다. 다른 AI 모델에서도 Z%로 같은 경향을 보였다."
- 한계: AI 심사위원은 실제 재배 경험이 없고 모델의 편향을 가질 수 있다. 이를 줄이기 위해 블라인드, 반복, 교차 모델, 순서 편향 점검을 함께 했다. 현장 실측과 실제 사용자 평가는 하지 않았다.
