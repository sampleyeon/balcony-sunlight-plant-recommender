# 식집사 앱 실행 패키지 안내 (2026-11-13)

이 폴더 하나를 Hugging Face Spaces에 올리면, 규연 님의 React 앱이 **주소·동·층·창 방향**을 보내고 **월별 직사광, 실내 조도, 식물 Top3**를 받아 갈 수 있습니다. QGIS는 필요 없습니다. 원본 파일(app_engine/, suitability/, building/)은 하나도 바꾸지 않았습니다.

## 1. 흐름

```
React 앱 ──GET /api/recommend?addr=..&dong=..&floor=..&facing=..──▶ app.py (FastAPI)
                                                                       │
   engine/recommend.py  recommend(주소, 동, 층, 방향)                   │
     ├─ engine/analyze.py      sun_engine(직사광) + indoor_lux(실내 조도)  ← data/dsm.npy 등
     └─ engine/plant_suitability.py  통합 추천엔진 score() 그대로 사용     ← data/plant_data.csv, ASOS
                                                                       │
React 앱 ◀──────────── JSON (월별 일조·조도 + 베란다작물/실내식물 Top3) ──┘
```

recommend.py는 점수 규칙을 새로 만들지 않습니다. analyze() 결과를 통합 추천엔진이 읽던 표 모양(window_sun_monthly, indoor_lux)으로 바꿔서 `plant_suitability.score()`에 넘기고, 결과를 화면에서 쓰기 좋게 정리만 합니다.

## 3. 규연 님 React 앱에서 부르는 법

서버 방식은 **FastAPI**로 골랐습니다. React에서 `fetch` 한 줄이면 되고, 주소 뒤에 `/docs`를 붙이면 브라우저에서 바로 눌러 볼 수 있는 시험 화면이 자동으로 생기기 때문입니다. (Gradio는 화면은 쉽지만 React에서 부르려면 전용 클라이언트를 따로 써야 합니다.)

```js
const API = "https://<허깅페이스아이디>-sikjipsa-api.hf.space";

async function getRecommend(addr, dong, floor, facing) {
  const q = new URLSearchParams({ addr, dong, floor, facing });
  const res = await fetch(`${API}/api/recommend?${q}`);
  const data = await res.json();
  if (!res.ok) throw new Error(data.detail);   // 400이면 detail 문구를 그대로 화면에 보여 주기
  return data;
}

// 예: getRecommend("솔샘로25길 28", "127", 7, "남")
```

- 창 방향 값: `북, 북동, 동, 남동, 남, 남서, 서, 북서`
- 400 오류: 성북구 밖 주소, 없는 동(그 주소의 동 목록을 알려 줌), 건물보다 높은 층, 잘못된 방향. `detail` 문구가 사용자용 안내입니다.
- 503 오류: 서버에 data 파일이 아직 없을 때
- 첫 계산은 1초 안팎, 같은 입력은 저장해 둔 결과를 바로 돌려줍니다.

### 응답에서 주로 쓰는 값

| 키 | 내용 |
| --- | --- |
| `building` | 찾은 건물 이름, 동, 층수, 위경도 |
| `months[]` | 12개월(2025-10 ~ 2026-09). `month_num`(1~12)으로 "이번 달"을 찾으면 됩니다 |
| `months[].direct_h`, `sun_grade` | 그 달 21일 직사광 시간, 등급(high/medium/low) |
| `months[].lux_1m`, `dli_1m` | 창에서 1m 실내 조도, DLI |
| `months[].top3["베란다작물"]`, `top3["실내식물"]` | 추천 식물 목록. 각 식물에 `S_final`, `S_light`, `S_temp`, `grade`, `limit`(광/온도 중 무엇이 부족한지), `light_basis` |
| `months[].note` | 추천이 없거나 3종보다 적을 때 보여 줄 문구 |
| `plants[]` | 30종 각각의 12개월 점수, `first_good_month`, `good_months`(적합한 달 목록) → 식물 상세·재배 달력 화면용 |
| `sun_monthly`, `lux_monthly` | 원래 analyze() 결과 (위치별 lux 전부) |

Top3 규칙은 통합 추천엔진과 같습니다. 제철이고 50점 이상인 식물만 나오기 때문에 3종보다 적을 수 있고, 동점은 같은 순위라서 3종보다 많을 수도 있습니다(예: 7월 100점 6종).

## 4. 서연 님이 할 일

1. **QGIS에서 `tools/prepare_app_data.py` 실행** (위쪽 경로 3개만 확인). `gis\app_data` 폴더에 `dsm.npy`, `dsm_meta.json`, `buildings_seongbuk.csv`가 생깁니다.
2. 이 세 파일을 `app_package/data/`에 넣습니다.
3. 노트북에서 시험해 봅니다 (명령 프롬프트, app_package 폴더에서):
   ```
   pip install -r requirements.txt
   python engine/recommend.py "도로명주소" 동번호 층 방향
   ```
   A 세대(꿈의숲아이파크 709동 18층 남동)를 넣어서 직사광이 `building/final_ABC_20261108/window_sun_monthly.csv`와 비슷하게 나오는지 보면 됩니다.
4. **Hugging Face Spaces 만들기**: New Space → SDK는 **Docker**, 템플릿 Blank → Files 탭에서 app_package 안의 파일을 폴더째 올립니다. `dsm.npy`는 크지만(수십 MB) 웹 업로드로 올라갑니다.
5. 빌드가 끝나면 `https://<아이디>-<스페이스이름>.hf.space/docs`에서 시험해 보고, 이 주소를 규연 님에게 전달합니다.

## 5. 확인한 것

- **최종 A·B·C로 같은 결과 확인**: `building/final_ABC_20261108/`의 직사광·실내 조도를 넣어 원본 `plant_suitability.py`를 임시 폴더에서 돌린 결과와, 같은 숫자를 analyze() 모양으로 바꿔 recommend.py에 넣은 결과가 1,080행(3세대 × 12개월 × 30종) 모두 일치했습니다. 월별 Top3도 모두 같았습니다. (`python tests/check_ABC.py`)
- **가짜 DSM 전체 시험**: 남쪽 40m 앞에 30m 건물을 둔 가짜 동네에서 12월 직사광이 15층 9.3시간, 1층 1.7시간으로 나왔고, 잘못된 입력 4가지는 모두 안내 문구와 함께 400으로 돌아왔습니다. (`python tests/test_fake_dsm.py`)
- 실제 서버(uvicorn)로 띄워서 React와 같은 방식(GET, 다른 주소에서 호출 허용)으로 불러 보았습니다.

## 6. 알아 둘 점

- **9월 추천**: 공유 폴더의 `suitability/input/OBS_ASOS_TIM_서울108.csv`는 9월 1일에서 끝나서 9월 기온 점수가 비어 있습니다. 앱 패키지에는 9월 30일까지 있는 ASOS 파일(실내 조도 계산에 쓰던 것)을 넣었습니다. 두 파일은 겹치는 8,041시간의 기온·일사가 모두 같아서, 9월이 채워진다는 점만 다릅니다.
- `suitability/input/`의 `window_sun_monthly_ABC.csv`, `indoor_lux.csv`는 아직 옛 시나리오(정릉 7층, 성북동 1층)입니다. 최종 A·B·C 값은 `building/final_ABC_20261108/`에 있어서 검증과 예시에는 그쪽을 썼습니다.
- 앞으로 `suitability/plant_suitability.py`의 규칙을 바꾸면 `engine/plant_suitability.py`에도 같이 복사하고, `engine/analyze.py`의 `ENGINE_VERSION`을 올려야 옛 저장 결과가 무시됩니다.
- 전자지도에 없는 건물(예: 돈암풍림 103동)은 지금은 "주소표에 없음"으로 안내됩니다. 시나리오 B를 앱에서 보여 주려면 주소표에 그 건물 행을 보충해야 합니다.
- RAG 설명(농사로 재배 정보 + LLM)은 이 패키지에 들어 있지 않습니다. 붙일 때는 `/api/recommend` 결과의 Top3와 점수를 LLM에 넘기는 식으로 연결하면 됩니다.
